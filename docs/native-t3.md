# 使用 T3 原生网络访问

本项目优先使用 T3 的公开接口和配置，不修改安装包，不添加中间转发服务。

## 图形界面入口

在当前桌面版中核对：

```text
Settings -> Sharing & access -> Network access
```

开启会重启桌面客户端。官方文档和对应源码说明了网络暴露模式、配置保存及客户端退出时的服务关闭行为，见 [来源](sources.md)。

T3 原生网络模式会监听网络接口。基础方案依赖上游不暴露 T3 TCP 端口、WireGuard zone 的窄范围转发规则以及 T3 原生认证。若要求连家庭 LAN 中其他设备也不能访问，应另外核对电脑的有效防火墙策略。

仅添加一条窄范围 allow 规则，不会自动抵消已有的宽范围 allow；不要对此作错误保证。

## 原生自定义端口

源码基线支持 `T3CODE_PORT`。这是 T3 自己读取的参数，不是额外代理。

新部署通常选择空闲的 `3773`。假设原有手机入口使用 `3774`，也可以让原生 T3 直接使用 `3774`，省去手机改地址。此时必须先识别并停止占用该端口的旧入口，不能同时监听。

这个用户级环境变量也可能影响同一用户以后启动的其他 T3 进程，因此部署记录应包含旧值及恢复方式。

## Windows 辅助脚本

脚本只用于执行一次配置，不创建服务、计划任务、端口转发或后台检测。

先显示计划：

```powershell
.\scripts\enable-native-access.ps1 `
  -AppExecutable 'C:\Path\To\T3 Code.exe' `
  -Port 3773
```

确认实际 T3 home；使用自定义 home 时加 `-T3Home`。正常关闭 T3 后再应用：

```powershell
.\scripts\enable-native-access.ps1 `
  -AppExecutable 'C:\Path\To\T3 Code.exe' `
  -Port 3773 `
  -Apply -Start
```

如果系统策略阻止本次脚本运行，可以在已授权的前提下使用**进程范围**的执行选项；不要永久降低系统执行策略。

脚本会：

- 在私有 T3 home 中备份桌面设置和旧端口变量。
- 保留现有 JSON 字段，设置 `serverExposureMode` 为 `network-accessible`。
- 保存用户级 `T3CODE_PORT`，并为本次重新启动明确设置相同值。
- 只有提供 `-Start` 才打开原来的 T3 客户端。

它不会关闭正在运行的 T3，不会抢占未知进程使用的端口，也不会替你完成手机配对。输出“configurationSaved”只是配置结果，不是远程连接成功证明。

不要在运行中的 T3 旁边直接改同一个设置文件：客户端可能在保存窗口状态或退出时覆盖磁盘内容。实际版本不再支持上述字段时，停止套用本脚本，按当前官方实现调整。

## 旧入口迁移顺序

1. 识别旧端口的 owner、旧启动任务 action 和关联文件。
2. 准备私有备份及明确的回退步骤。
3. 在一次切换窗口中正常关闭 T3，停止旧入口占用，启用原生配置并重开 T3。
4. 验证端口 owner 已变成 T3，HTTP、认证和手机路由正常。
5. 再移除旧转发和任务。

不应为了保留旧入口而永久增加一层端口转换。T3 在同一原生端口可直接满足需求时，使用原生能力。

## 验证

```powershell
Get-NetTCPConnection -LocalPort 3773 -State Listen |
  Select-Object LocalAddress, LocalPort, OwningProcess
```

继续核对 `OwningProcess` 的实际程序路径。端口号按实际设置替换。

网络模式下可能看到 `0.0.0.0`，它表示绑定所有 IPv4 接口，**不是自动映射公网**。公网暴露还取决于路由、NAT 和防火墙。

正常关闭 T3 后检查监听消失，再重新打开检查恢复。电脑重启测试应安排在用户允许时；仅检查环境变量不能冒充实际重启测试。
