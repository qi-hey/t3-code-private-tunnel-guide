# 验收与排错

## 分层验收表

| 层次 | 应观察到的证据 | 单独不足以证明的事 |
| --- | --- | --- |
| 原生服务 | LAN 可达监听，owner 是 T3 | 手机已经通过公网连上 |
| WireGuard | 最近握手随手机测试更新 | T3 的 TCP 回程和认证正常 |
| 路由 | 请求到电脑、返回到手机隧道地址 | 配对凭据有效 |
| 应用认证 | 未认证拒绝，合法配对成功 | 不存在其他独立的数据外发 |
| 手机业务 | 当前使用私有路由，可交互和加载媒体 | 已经占满上传带宽 |
| 持久化 | 实际重开 T3 / 重启电脑后的结果 | 仅看到保存配置就等于重启通过 |

基础 HTTP 检查可在具备 curl 的受控设备执行：

```sh
curl --noproxy '*' --max-time 8 -o /dev/null -w '%{http_code}\n' http://192.168.50.100:3773/
```

Windows 使用 `curl.exe`，避免 PowerShell 的同名别名差异。

在本教程核对的 T3 基线中，未认证的以下请求应被拒绝：

```sh
curl --noproxy '*' --max-time 8 -o /dev/null -w '%{http_code}\n' \
  -X POST -H 'Content-Type: application/json' -d '{}' \
  http://192.168.50.100:3773/api/auth/websocket-ticket
```

预期为 `401`。该路径属于版本相关实现，使用前核对源码；不能在路由已被移除的版本里把 `404` 当作认证成功证据。

合法认证以真实手机配对为准。自动化测试需要临时会话时，只授予所需权限、短期有效，并在结束后撤销；不把 token 放进命令行参数或公开输出。

## 正向和负向测试

- 手机使用蜂窝网络，确认当前 T3 路由是私有入口。
- 对真实图片、视频做加载测试；拖动视频时检查范围请求和播放是否正常。
- 尝试本隧道不应允许的路由器管理、电脑 SMB 和其他 LAN 地址，预期无法访问。
- 验证原有代理订阅、DNS 和其他应用仍正常。
- 正常退出 T3，检查原生端口消失；重新打开后恢复。
- 检查本次替代的转发进程、轮询任务和端口代理确实不存在。

负向测试只针对用户自己的网络和本次隔离目标，不扫描外部地址或整片网络。

## 常见故障

| 现象 | 优先排查 |
| --- | --- |
| 没有最新握手 | 公网入口、UDP 映射、DDNS、密钥对应关系、FlClash 内核支持及实际生效配置 |
| 握手正常，T3 不通 | T3 是否仅绑定 loopback、电脑防火墙、指定端口、电脑到 WireGuard 子网的回程 |
| 同一 Wi-Fi 可用，蜂窝不可用 | 本地直连绕过了隧道、上游 NAT、错误公网接口或 UDP 入口 |
| 请求到达电脑，但无响应返回 | 默认网关、静态回程、多 WAN 或 OpenClash 策略路由 |
| 开启 OpenClash 后异常 | 外层 UDP 是否直连、透明代理接管、具体 mark 与路由表 |
| HTTP 200，但 App 失败 | 认证、会话状态、WebSocket、手机保存的入口及路由优先级 |
| T3 重开后换回旧端口 | 实际进程环境、用户级 `T3CODE_PORT`、不同 home 或不同安装版本 |
| 公网地址变化后失联（隔天自动退回 T3 Connect） | 核对 OpenWrt `wg show` 最近握手时间；检查客户端是否写死了旧 PPPoE IP、DDNS 是否正常同步、域名是否误开橙云代理，以及多拨映射是否漏勾当前在线拨号口 |
| DDNS 频繁切换 IP、隧道偶发重连 | 双拨负载均衡下 DDNS 每次请求命中不同出口，改用 [粘滞防跳动探测](ddns-and-multi-wan.md) 并在主路由把 UDP 映射覆盖全部公网拨号口 |
| 手机端私有线路显示“地球”图标而非 Wi-Fi | 家庭 LAN 使用了非 RFC 1918 网段时客户端按公网图标展示；只要公网未映射 T3 TCP 端口即仍属局域网地址，以线路是否标为“正在使用”和 OpenWrt 握手为准 |
| 电脑重启或续租后 LAN IP 变更导致失联 | 核对主路由 DHCP 静态分配是否按实际网卡 MAC 绑定了目标 LAN IP |
| 视频开头能播，拖动失败 | Range 请求、媒体格式、文件访问授权或客户端播放实现 |

## 速度怎么报告

记录测试方向、文件大小、冷缓存或热缓存、首帧耗时、完整下载耗时和实测流量。

WireGuard 本身不会凭空扩大家庭上行带宽。秒开可能来自较低延迟、首段缓冲、缓存或较低视频码率，不等于整段视频已上传，更不能据此认定上传带宽“拉满”。

可以根据传输字节和时间计算平均吞吐，但平均值不能代替初始峰值。没有运营商上行速率或同时段实测基线时，不报告“已达到带宽上限”。

## 交付措辞

可以说：

> 原生监听与认证检查通过。手机蜂窝网络直连已测试；T3 重开已测试；电脑整机重启尚未测试。

不可以说：

> 全部安全、不会泄露、已经彻底本地化、官方果然偷数据。

验收记录只写实际证据。包含真实地址和设备信息的详细记录应保持私有。
