# 隐私、网络指控与责任边界

## 指控是谁提出的

本教程回应的是部分网络讨论中的未经证实说法。**“T3 Code 官方免费隧道偷数据”不是项目需求提出者、教程作者或维护者提出、认可或证实的结论。**

项目的技术目标是提供私有直连路径。不得将本项目的存在、部署成功或速度改善解释为该指控成立，也不得在转载时改成“作者发现官方偷数据”。

本项目不为未经核实的第三方指控背书；同样，不会宣称已经审计官方生产服务器、证明其绝不收集任何信息。涉及具体行为的判断应建立在能够复核的证据上。

## 不混淆四类数据路径

| 路径 | 本方案的作用 |
| --- | --- |
| 手机访问电脑的 T3 内容 | 选中私有直连路由后，通过自己的 WireGuard 入口传输 |
| T3 官方隧道的控制连接或备用路由 | 不会仅因配置 WireGuard 自动关闭，应单独检查 T3 Connect 设置 |
| 遥测、崩溃报告、检查更新 | 属于另一类连接，需要依据当前版本的设置与实现单独检查 |
| 向 AI 服务商发送模型请求 | 仍按所选服务商、模型和工具配置发送；本教程没有改成本地推理 |

官方中转不再承担**这条选中的业务访问路径**，不等于整个应用已离线，也不等于没有任何请求访问官方域名。

如果目标还包括停止官方隧道的后台连接，应在直连验证成功后单独关闭 T3 Connect，并验证实际状态。不要通过删除账号、清空认证库或阻断所有未知域名实现这一目标。

## 加密在哪里结束

基础拓扑：

```text
手机 === WireGuard 加密 === OpenWrt --- 家中局域网 HTTP --- T3 电脑
```

WireGuard 提供隧道中的加密和对端认证。终点在 OpenWrt 时，解密发生在 OpenWrt；局域网 HTTP 段不是 TLS。

因此：

- 手机中显示 `http://` 不代表承载它的公网隧道是明文。
- 也不能把这种部署描述为“手机一直加密到 T3 进程”。
- 对家庭局域网的信任是一个明确选择。需要保护该段时，应另加 HTTPS 或把 WireGuard 终点移到电脑。
- VPN 不是匿名保证。公网地址、通信时间和流量规模等元数据仍可能对路径中的网络运营方可见。

T3 自身的配对和会话认证必须保留。隧道认证与应用认证解决的是不同问题。

## 哪些现象不能单独证明“偷数据”

- 服务免费。
- 客户端访问某个统计域名。
- 隧道经过中转服务器。
- 图片加载较慢，而直连后较快。
- 客户端源码存在日志或遥测代码。

这些现象可以成为进一步检查的线索，但没有自动说明上传内容、用途、用户授权、保存期限或服务器实际处理方式。

若要分析一项具体数据收集行为，应说明观察版本、触发条件、请求目的地、可确认的数据字段和取证限制。不要把仅有 URL 的截图描述为“完整流量审计”，也不要把客户端静态代码描述为服务端审计。

## 公开教程与实际部署分开

公开文件只保留通用步骤和示例。实际地址、账号、密钥、配对信息、设备标识、原始抓包、日志和配置必须在私有环境保存。

自建后，部署者需要维护自己的密钥、设备更新、路由、防火墙和备份。这是运维职责的变化，不是对第三方不当行为的认定。
